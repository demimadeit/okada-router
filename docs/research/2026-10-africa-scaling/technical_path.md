## Key Question 1: Training vs fine-tuning vs no training — what actually needs training?

### Takeaway
Nothing in the gateway *requires* training today: routing is rule-based on network signals and the local model is an off-the-shelf GGUF. The three places training *could* add value are (a) a learned routing/quality policy (needs quality labels the telemetry does not yet capture), (b) a LoRA/QLoRA language adapter for Nigerian/East-African languages (cheap in GPU dollars, expensive in data curation), and (c) distilling cloud answers into the local model from logged prompts (feasible, but the project currently logs no prompt text). Honest verdict: a 1.5–3B model can serve Swahili and Hausa usefully, Yoruba/Igbo marginally, Nigerian Pidgin plausibly via English proximity; none of this is proven for Okada's exact model without running IrokoBench/AfriQA-style evals locally.

### Cited Findings

**(a) Learned routing policy (RouteLLM-style)**
- RouteLLM trains routers on human preference data from Chatbot Arena; each data point is a prompt plus a pairwise comparison (win/lose/tie) between two models. Arena data is sparse for many model pairs, so the authors cluster models into tiers and add golden-label (MMLU validation) and LLM-judge augmentation — [RouteLLM arXiv 2406.18665](https://arxiv.org/html/2406.18665v2) [verified-primary]
- Result: matrix-factorization router reaches 95% of GPT-4 quality using 26% GPT-4 calls on Arena data alone; with LLM-judge augmentation 14% of calls (75% cheaper than random routing) — [RouteLLM arXiv](https://arxiv.org/html/2406.18665v2) [verified-primary]
- A third-party summary gives the base dataset as ~80k Arena battles; I could not confirm that count in the paper excerpts — [Athina summary](https://hub.athina.ai/research-papers/routellm-learning-to-route-llms-with-preference-data) [secondary, unverified]
- RouteLLM framework and ICLR 2025 acceptance — [LMSYS blog](https://lmsys.org/blog/2024-07-01-routellm/); [ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/5503a7c69d48a2f86fc00b3dc09de686-Abstract-Conference.html) [verified-primary]
- Okada's telemetry currently records network state, decision, attempts, bytes, tokens, latency and success — but no prompt text and no quality signal — [gateway/telemetry.py](/home/user/okada-router/gateway/telemetry.py) [verified, local file]

**(b) Fine-tuning a 1–3B model for African languages: GPU cost**
- RunPod on-demand A100 80GB: $1.19/hr (RunPod pricing page, July 2026); other 2026 listings $1.39–1.49/hr for PCIe/SXM; Secure Cloud 20–30% above Community — [RunPod pricing](https://www.runpod.io/gpu-cloud/pricing) [verified-primary]; [computeprices tracker](https://computeprices.com/providers/runpod/gpus/a100-pcie-80gb) [secondary]; [deploybase](https://deploybase.ai/articles/runpod-gpu-pricing) [secondary]
- Vast.ai A100 80GB ~$0.50–0.80/hr on (often unverified) community hosts — [Spheron comparison](https://www.spheron.network/blog/runpod-vs-vastai-2026/) [secondary]
- Only runtime figure found: a third-party estimate of ~20 h × $1.19 ≈ $24 for QLoRA on a 7B model with 100k examples; no measured 3B figure found — [deploybase A100 on RunPod](https://deploybase.ai/articles/a100-on-runpod-pricing-specs-how-to-rent) [secondary, estimate]
- A knowledge-injection paper fine-tuned Qwen2.5-3B with a LoRA adapter for 5 epochs on one GPU using 30 synthetic questions per target item (self-distillation, no external teacher) — [arXiv 2412.14964](https://arxiv.org/pdf/2412.14964) [verified-primary]

**(b) Datasets available**
- InkubaLM (Lelapa): 0.4B params trained from scratch on ~1.9B tokens of Swahili, Yoruba, Hausa, isiZulu, isiXhosa (+English/French = 2.4B tokens); MobileLLM-like architecture, vocab 61,788; released Inkuba-Mono and Inkuba-Instruct datasets; claims parity with much larger models on MT, QA, AfriMMLU, AfriXNLI — [InkubaLM arXiv 2408.17024](https://arxiv.org/html/2408.17024v1); [Lelapa blog](https://lelapa.ai/blog/inkubalm-small-language-model) [verified-primary]
- Inkuba-Instruct size as stated by Lelapa: 148M training samples, 65M validation, 55M test across six tasks (another summary says five tasks) in the same five languages — [Lelapa InkubaLM page](https://lelapa.ai/inkubalm-a-small-language-model-for-low-resource-african-languages); [HF dataset](https://huggingface.co/datasets/lelapa/Inkuba-instruct) [verified-primary; sample counts look like per-row counts of templated examples, treat with caution]
- AfriQA: 12,000+ cross-lingual QA examples in 10 African languages, CC-BY-SA-4.0, HF `masakhane/afriqa` — [HF AfriQA README](https://www.huggingface.co/datasets/masakhane/afriqa/blob/e27efe56b71d639f6713c1287aeba1753afaea62/README.md) [verified-primary]
- AfriSenti: 110,000+ annotated tweets in 14 African languages incl. Nigerian Pidgin, Hausa, Igbo, Yoruba (NaijaSenti is its Nigerian subset) — [HF AfriSenti-Twitter](https://huggingface.co/datasets/HausaNLP/AfriSenti-Twitter) [verified-primary]
- Mozilla Common Voice speech (for a future voice channel): Hausa v24.0 = 12.62 h recorded, **4.22 h validated**, 60 speakers; Igbo v24.0 = 13.22 h recorded, **0.4 h validated** (suspiciously low, verify); Yoruba v25.0 (Mar 2026) = 8.14 h recorded, **5.82 h validated**, 133 speakers. Swahili figure not found. CC0 but datasheets forbid re-hosting — [CV Hausa 24.0](https://datacollective.mozillafoundation.org/datasets/cmj8u3p6w00alnxxbby9yqbms); [CV Igbo 24.0](https://datacollective.mozillafoundation.org/datasets/cmj8u3p9a00c5nxxb7jwi217j); [CV Yoruba 25.0](https://datacollective.mozillafoundation.org/datasets/cmn29vsoh019amm07d95id0mo) [verified-primary]
- IrokoBench: 17 typologically diverse African languages across NLI, math reasoning and knowledge QA; 10 open + 6 proprietary LLMs tested; best open model Gemma 2 27B reached only 63% of GPT-4o; translate-test (MT to English first) helps English-centric large models — [IrokoBench arXiv 2406.03368](https://arxiv.org/pdf/2406.03368); [MSR page](https://www.microsoft.com/en-us/research/publication/irokobench-a-new-benchmark-for-african-languages-in-the-age-of-large-language-models/) [verified-primary]
- AfroBench: GPT-4o and Gemma 2 27B score +25 to +40 points better in English than in African languages — [AfroBench arXiv 2311.07978](https://arxiv.org/html/2311.07978v5) [verified-primary]
- Lelapa Vulavula API (hosted transcribe/translate/converse): $9.99/mo for 1,000 calls, $49/mo for 10,000, $499/mo for 500,000; overage $0.005 / $0.003 per call; language coverage documented mainly for isiZulu, Sesotho, isiXhosa, Afrikaans — [Lelapa docs plans](https://docs.lelapa.ai/overview/plans.md); [AWS Marketplace listing](https://aws.amazon.com/marketplace/pp/prodview-li2rffe3oqt2a) [verified-primary]

**(c) Distillation of cloud answers into the local model**
- DistilQwen2.5 (Alibaba, ACL Industry 2025): proprietary LLMs used as teachers to select/rewrite instruction–response pairs, then white-box logit distillation after SFT — [ACL 2025 industry](https://aclanthology.org/2025.acl-industry.4) [verified-primary]
- Community 1.5B students distilled from Qwen2.5-7B-Instruct used a 96,000-example set and 1,500 optimizer steps — [Featherless model page](https://featherless.ai/models/huggingFacing/qwen2.5-7b-to-1.5b-gkd-paper100k-step1500-seed10) [secondary, self-reported]
- torchtune has a documented Llama knowledge-distillation recipe — [torchtune KD tutorial](https://docs.pytorch.org/torchtune/0.4/tutorials/llama_kd_tutorial.html) [verified-primary]
- Digital Green fine-tuned GPT-4o Mini (a smaller hosted model) rather than relying on frontier models to keep infrastructure cost down — [Digital Green / OpenAI post](https://digitalgreen.org/tag/community-video/) [verified-primary, promotional]

**Existing small models and their African-language coverage**
- Gemma 3 family: ">140 languages" is a family-wide claim; 1B is text-only with 32K context; NVIDIA's model card shows a steep 1B→4B multilingual gap: MGSM 2.04 vs 34.7, Global-MMLU-Lite 24.9 vs 57.0 — [NVIDIA NIM Gemma 3 1B card](https://docs.api.nvidia.com/nim/reference/google-gemma-3-1b-it); [build.nvidia.com card](https://build.nvidia.com/google/gemma-3-1b-it/modelcard) [verified-primary]
- Qwen3 (0.6B/1.7B/4B dense): family claims 119 languages and dialects, pre-trained on 36T tokens; the per-language list was not retrieved in this session — [DEV summary](https://dev.to/projedefteri/qwen3-hybrid-thinking-and-superior-performance-in-119-languages-proje-defteri-56d2) [secondary]
- Aya Expanse 8B covers 23 languages; the list (Arabic, Chinese, Czech, Dutch, English, French, German, Greek, Hebrew, Hindi, Indonesian, Italian, Japanese, Korean, Persian, Polish, Portuguese, Romanian, Russian, Spanish, Turkish, Ukrainian, Vietnamese) includes **no** Sub-Saharan language — [Ollama aya-expanse page](https://registry.ollama.ai/library/aya-expanse:8b); [Cohere paper](https://cohere.com/research/papers/aya-expanse-combining-research-breakthroughs-for-a-new-multilingual-frontier-2024-12-06) [verified-primary]
- Lugha-Llama (Princeton, 2025): three 8B models continued-pretrained on the WURA corpus (16 African + 4 colonial languages); best among similar-size baselines on IrokoBench, +10% over base on AfriQA; AfroLlama-v1 (LoRA continual pretraining of Llama 3 8B on Swahili, Xhosa, Zulu, Yoruba, Hausa, English) scores below it (AfriXNLI avg 37.6 vs 40.8) — [Lugha-Llama arXiv 2504.06536](https://arxiv.org/pdf/2504.06536); [Princeton blog](https://blog.ai.princeton.edu/2025/04/22/lugha-llama-adapting-large-language-models-for-african-languages) [verified-primary]
- Jacaranda Health's UlizaLlama: 7B Llama-based, built on `kiswallama-pretrained` continually pretrained on 321,530,045 Swahili tokens; powers the PROMPTS helpdesk — [HF UlizaLlama README](https://huggingface.co/Jacaranda/UlizaLlama/blob/6775e74bddd064bae0aef38f93423f52bb0fd00a/README.md?code=true) [verified-primary]
- No results found for a model named "Cheetah" or "Sabiá" in African-language context (Sabiá is Portuguese/Brazilian; not relevant).

### Inferences
- **Do we need to train? No, not to ship.** Routing decisions are driven by network probes, not model quality; a learned router only pays off once Okada captures a quality signal (thumbs-up/down, LLM-judge score on replay, or "user re-asked within 60 s" as an implicit negative) alongside the existing network features. RouteLLM needed tens of thousands of labelled pairs plus augmentation; Okada's current JSONL lacks prompts and labels, so step one is a schema change (hashed prompt, language-ID, response-quality label), not a training job. [estimate]
- **Cheapest useful "training" is a LoRA language adapter**: at $1.19/hr A100, a QLoRA pass over a few hundred thousand Inkuba-Instruct/AfriQA/AfriSenti examples on a 1.5–3B base is in the **$5–40 range of GPU time** (extrapolating from the 7B/100k/20h third-party estimate); the real cost is data cleaning and evaluation, not compute. [estimate]
- **Distillation is viable only after prompt logging is opt-in and consented**: log (prompt, cloud answer) pairs from the "healthy" route, filter for PII, and SFT the local GGUF base on them; the 96k-example community recipes suggest ~10^4–10^5 pairs is the working range, so a pilot with a few hundred daily users would reach that in months. [estimate]
- **Which languages a 1.5–3B Q4 model can serve usefully** (my honest reading of the benchmarks): Swahili is the best-resourced (321M-token Swahili pretraining exists, InkubaLM/Lugha-Llama cover it); Hausa next (in InkubaLM, AfroLlama, WURA); Yoruba and Igbo are weaker (tiny validated speech data, low-resource text); Nigerian Pidgin is not in InkubaLM's five languages at all but is close enough to English that general small models produce passable output. The 1B→4B Gemma multilingual gap (MGSM 2→35) means **1B-class models should be treated as English/Swahili-only; 3–4B is the floor for the other languages**, which collides with the 8GB-CPU box budget (see Q4). [estimate]
- Translate-test (IrokoBench finding) suggests a practical architecture: a small local MT step (or Vulavula API when online) into English, then the English-centric small model, then MT back — rather than hoping the 1.5B model reasons natively in Yoruba. [estimate]

### Gaps
- Per-language IrokoBench scores for Hausa/Yoruba/Igbo at the 1–4B scale were not retrievable (the arXiv table rendered garbled). Needs a local eval run.
- Qwen3's official 119-language list (whether Hausa/Yoruba/Igbo/Swahili are included) not retrieved; check the Qwen3 model card.
- No measured QLoRA wall-clock for a 3B model on a given dataset size; the $5–40 figure is an extrapolation.
- No source found on InkubaLM's per-language scores or on how it runs under llama.cpp (GGUF availability unknown).
- NaijaSenti exact size and MasakhaNEWS size were not retrieved.
- Swahili Common Voice hours not retrieved.

## Key Question 2: API keys — free/near-free tiers for a pilot and BYO vs pooled keys

### Takeaway
Yes, the cloud rungs need API keys, but a pilot can run on free tiers that are per-organisation and rate-limited (not token-capped): Groq, Gemini Flash, OpenRouter `:free` models, SambaNova, Cloudflare Workers AI, Cerebras (trial-like). None is large enough to serve a multi-shop deployment from one pooled key, which is exactly why a gateway should meter per-tenant virtual keys over a pooled upstream key *and* accept BYO keys. All figures below are from secondary pages because the official docs were unreachable; treat them as "order of magnitude, re-verify."

### Cited Findings
- **Groq**: free tier is rate-limited per model (RPM/RPD/TPM/TPD), not a monthly token budget; limits apply at organisation level; one 2026 table gives Llama 3.3 70B 30 RPM / 1,000 RPD / 12,000 TPM, and gpt-oss-120b (Okada's default "large") 30 RPM / 1,000 RPD / 8,000 TPM / 200,000 TPD; another page says 14,400 RPD for 70B models — figures conflict — [eesel Groq pricing](https://eesel.ai/blog/groq-pricing); [costbench Groq free plan](https://costbench.com/software/llm-api-providers/groq/free-plan/); [CloudZero](https://www.cloudzero.com/blog/groq-pricing/) [secondary, conflicting]
- Adding a card with zero minimum spend reportedly unlocks up to 10× the free limits on Groq — [CloudZero](https://www.cloudzero.com/blog/groq-pricing/) [secondary, unverified]
- **OpenRouter** `:free` models: 20 requests/min for all accounts; 50 requests/day if lifetime credit purchases < $10, 1,000/day once ≥ $10 has ever been bought; enforced globally, extra keys don't help — [OpenRouter free-LLM comparison](https://openrouter.ai/blog/tutorials/free-llm-apis-compared/) [verified-primary blog]; [TrueFoundry](https://www.truefoundry.com/es/blog/openrouter-rate-limits-your-free-tier-depends-on-what-youve-already-paid); [kingy.ai limits check 2 Aug 2026](https://kingy.ai/?p=927524) [secondary]
- **Gemini API free tier**: limits are per project, RPD resets midnight Pacific, 429 RESOURCE_EXHAUSTED on breach — [Google rate limits doc](https://ai.google.dev/gemini-api/docs/rate-limits?authuser=1) [verified-primary snippet]. Widely cited free-tier number for 2.5 Flash is 15 RPM / 1,500 RPD / 1M TPM (Flash-Lite 30 RPM), but an April 2026 page claims a cut to 5 RPM / ~100 RPD and Pro going paid-only — [rapidevelopers](https://www.rapidevelopers.com/md/ai-api-limits-performance-matrix/gemini-2-5-flash); [agentdeals April 2026](https://agentdeals.dev/gemini-api-pricing-changes) [secondary, conflicting]
- **SambaNova** free tier: 20 RPM / 20 RPD / 200,000 TPD, only while no payment method is attached — [novita free API comparison](https://blogs.novita.ai/free-llm-api-comparison-2026/) [secondary]
- **Cloudflare Workers AI**: 10,000 Neurons/day free, then $0.011 per 1,000 Neurons; allowance is in Neurons (compute), so long contexts burn it faster — [aireiter quota comparison](https://aireiter.com/blog/free-llm-api-quota-comparison); [agentdeals free APIs](https://agentdeals.dev/free-llm-apis) [secondary, consistent across sources]
- **Cerebras**: described variously as 1M tokens/day trial needing a verified payment method, or a permanent free tier whose model selection shrank by July 2026 — [novita](https://blogs.novita.ai/free-llm-api-comparison-2026/); [mydealz July 2026](https://www.mydealz.de/deals/sammeldeal-kostenlose-ki-api-kapazitaten-fur-entwickler-gemini-groq-openrouter-cloudflare-workers-ai-cerebras-hugging-face-2783697) [secondary, conflicting]
- **Mistral**: one source says all models free at 1B tokens/month but 2 RPM; another lists it as free without limits stated — [novita](https://blogs.novita.ai/free-llm-api-comparison-2026/) [secondary, conflicting]
- **Together** free tier: no 2026 figure surfaced in this session.
- **Metering pattern (LiteLLM proxy)**: virtual keys with per-key/per-team budgets (`max_budget`, `budget_duration`), model restrictions and expiry; `/key/info` and `/spend/keys` for spend; Prometheus `litellm_key_spend`; recommended pattern is to keep the upstream provider key only inside the proxy and issue one virtual key per customer — [elest.io LiteLLM guide](https://blog.elest.io/litellm-stop-burning-money-on-llm-apis-virtual-keys-cost-tracking-and-guardrails/); [LiteLLM budget alerts docs mirror](https://www.mintlify.com/BerriAI/litellm/proxy/budget-alerts); [mittwald LiteLLM key management](https://developer.mittwald.de/docs/v2/platform/aihosting/dedicated/litellm/) [secondary + docs mirror]
- Okada already reads `GROQ/OPENAI/ANTHROPIC/GEMINI_API_KEY` from env, first-found = primary, second = failover, and has `OKADA_API_KEY` bearer auth — [README](/home/user/okada-router/README.md); [docker-compose.yml](/home/user/okada-router/docker-compose.yml) [verified, local]

### Inferences
- A single pooled free key yields roughly **1,000 requests/day on Groq or Gemini Flash and 50–1,000/day on OpenRouter** — enough for one shop or one clinic pilot, not for a fleet. Stacking several providers' free tiers behind Okada's existing failover (Groq → Gemini → OpenRouter free → Cloudflare) multiplies the daily budget to a few thousand requests/day for $0, which is a legitimate pilot strategy as long as 429s are treated as a "provider degraded" signal and routed around, not retried. [estimate]
- Right design for a product: **hybrid**. (1) Operator-pooled upstream keys with per-tenant virtual keys and hard daily budgets (LiteLLM-style `max_budget`), because shop owners will not create Groq accounts; (2) BYO keys as an override header/tenant config for NGOs/enterprises who already have accounts, with spend still metered locally from `usage` so the tenant sees cost; (3) the `degraded_max_tokens: 300` cap is already the most important cost lever and should become per-tenant. [estimate]
- The telemetry `COST_PER_M` table hardcodes four OpenAI/Anthropic prices and returns 0 for Groq/Gemini models — the pooled-key metering needs a real price table per provider before budgets mean anything. [verified local code → inference]

### Gaps
- Official Groq, Gemini, OpenRouter, Cerebras, Mistral and Together limit pages could not be fetched; all limits above are secondary and some conflict (notably Gemini free RPD: 1,500 vs ~100).
- Whether LiteLLM's virtual-key budgets still meter when a caller supplies their own provider key (true BYOK pass-through) was not answered by any source.
- No source on provider availability/latency specifically from Nigerian or Kenyan networks (e.g., which providers have African PoPs); Cloudflare's edge presence is the obvious candidate but was not verified for Workers AI inference location.

## Key Question 3: Mobile / on-device deployment options in 2026

### Takeaway
On-device LLMs on the phones Nigerians actually buy (Transsion sub-$100, typically 3–4 GB RAM; this RAM share was not verifiable) are limited to ~1B-class Q4 models at single-digit tokens/s on CPU with measurable thermal throttling and battery cost; flagship-only paths (Gemini Nano/AICore, Apple Foundation Models, MediaPipe LLM) do not reach that segment. The pragmatic route is a thin mobile SDK that talks to an Okada box on the LAN and falls back to a tiny on-device model (or to SMS/WhatsApp) only for short answers; the browser/PWA + WebGPU route is a no-install option but only on newer Qualcomm/ARM GPUs.

### Cited Findings
- **llama.cpp on Snapdragon**: official backend docs show Llama-3.2-1B Q4_0 on the Hexagon NPU at 45.69 tok/s decode and 122.5 tok/s prompt eval (device not named in snippet); llama.cpp supports CPU, Adreno GPU (OpenCL) and Hexagon NPU backends — [llama.cpp snapdragon README mirror](https://huggingface.co/datasets/echodict/llama.cpp/blob/main/docs/backend/snapdragon/README.md) [verified-primary doc, single run]
- A community dataset lists Llama-3.2-1B FP16 at 12 tok/s on Snapdragon 865 (2020 flagship) — [HF on-device-latency dataset](https://huggingface.co/datasets/dispatchAI/on-device-latency) [secondary, provenance unclear]
- A vendor blog estimates 1B Q4 at 35–45 tok/s CPU and 45–55 tok/s GPU on Snapdragon 8 Elite, ~800 MB RAM — [Ertas blog](https://www.ertas.ai/blog/llm-android-benchmarks-snapdragon-tensor) [secondary, no methodology]
- **llama.rn / React Native**: no benchmarks or thermal data found; a Flutter wrapper (`runanywhere_llamacpp`) exists — [pub.dev runanywhere_llamacpp](https://pub.dev/documentation/runanywhere_llamacpp/0.20.9/) [secondary]
- **ExecuTorch**: quantized Llama 3.2 1B prefill > 350 tok/s on Galaxy S24+ via XNNPACK + KleidiAI (prefill, not decode); verified on iPhone 15 Pro/Max, S24+, S22, OnePlus 12 (16 GB) — [Arm community blog](https://developer.arm.com/community/arm-community-blogs/b/ai-blog/posts/llm-inference-llama-quantized-models-executorch-kleidiai); [ExecuTorch PR 6486](https://github.com/pytorch/executorch/pull/6486/files) [verified-primary]; Vulkan Llama tutorial exists — [ExecuTorch Vulkan tutorial](https://docs.pytorch.org/executorch/main/backends/vulkan/tutorials/etvk-llama-tutorial.html)
- **MediaPipe LLM Inference (Google AI Edge)**: "optimized for high-end Android devices such as Pixel 8 and Samsung S23 or later"; Android API marked experimental/research; Gemma-3n E2B and E4B supported; production path is Gemini Nano via AICore "on select premium phones" — [MediaPipe LLM Inference Android guide](https://developers.google.com/edge/mediapipe/solutions/genai/llm_inference/android); [Google dev blog](https://developers.googleblog.com/en/large-language-models-on-device-with-mediapipe-and-tensorflow-lite/) [verified-primary]

## Key Question 5: Engineering gaps — streaming, queue replay, semantic cache, multi-tenant, PII, encryption, SMS/USSD/WhatsApp channels, LoRa/mesh

### Takeaway
Most listed gaps are ordinary backend work with known tools; the two with real research content are the semantic cache (use a small sentence-embedding model on CPU, not the LLM, and tune the threshold per workload) and the store-and-forward channels, where WhatsApp utility messages now cost ~$0.004–0.010 per message in Kenya/Nigeria since 1 Oct 2026 and SMS ~₦2–7, while LoRa mesh delivers only tens of bytes per second and is a demo, not a product channel.

### Cited Findings
- **Current gaps as stated by the project**: exact-match single-tenant cache with no PII handling; streaming wraps a complete response; queue journaled but not replayed after restart; no encryption at rest; single process; no mobile SDK — [README "Honest limitations"](/home/user/okada-router/README.md) [verified local]
- **Queue journal does not store messages** (only `n_messages`), so replay-after-restart is impossible from the journal as written — [gateway/queue_store.py](/home/user/okada-router/gateway/queue_store.py) [verified local]
- **Semantic cache embeddings**: GPTCache's original paper ran a small ALBERT-family embedder via ONNX on a 4-CPU laptop with ~0.3 s cache-hit latency vs ~3 s for a ChatGPT call — [GPTCache paper, NLP-OSS 2023](https://aclanthology.org/2023.nlposs-1.24.pdf) [verified-primary]; MeanCache found Llama-2-as-embedder significantly worse F1 than MPNet/ALBERT and ~0.04 s vs 0.005–0.009 s per embedding — [MeanCache arXiv 2403.02694](https://arxiv.org/pdf/2403.02694) [verified-primary]; a 2025 semantic-cache paper used all-MiniLM-L6-v2 (384-dim) for its speed/quality balance — [arXiv 2504.02268](https://arxiv.org/pdf/2504.02268) [verified-primary]; 2026 work on semantic caching for embeddings — [arXiv 2603.03301](https://arxiv.org/html/2603.03301v1) [verified-primary]
- llama.cpp can serve embeddings from GGUF: official `nomic-embed-text-v1` GGUF card documents llama.cpp embedding use (768-dim); community Qwen3-Embedding-0.6B GGUFs run via `llama serve -hf tinybiggames/Qwen3-Embedding-0.6B-GGUF:Q8_0` (1024-dim, 32k ctx) — [nomic GGUF card](https://huggingface.co/nomic-ai/nomic-embed-text-v1-GGUF/blob/main/README.md); [Qwen3-Embedding GGUF](https://huggingface.co/tinybiggames/Qwen3-Embedding-0.6B-GGUF) [verified-primary cards; no CPU latency numbers found]
- GPTCache authors: pick embedding model and similarity threshold by tolerance for cache errors — [GPTCache paper](https://aclanthology.org/2023.nlposs-1.24.pdf) [verified-primary]
- **SMS pricing**: Nigeria local bulk SMS ₦1.80 (MTN enterprise) to ₦6.00 retail; ₦5.62–7.00 per 160-char page per another guide; Africa's Talking generic rate listed as $0.0075 or $0.004 per SMS on two comparison pages (conflicting, not Nigeria-specific); Twilio Nigeria listed at $0.3868 (likely international route) — [bulksmsnigeria calculator](https://www.bulksmsnigeria.com/resources/sms-pricing-calculator); [sent.dm Nigeria](https://www.sent.dm/resources/sms-pricing/nigeria-sms-pricing); [courier AT comparison](https://www.courier.com/integrations/compare/africas-talking-vs-bandwidth); [textbee Twilio table](https://textbee.dev/sms-pricing/twilio) [secondary, conflicting]
- **WhatsApp Business Platform**: from 1 Oct 2026 Meta charges per utility message sent inside the 24-h service window (free since 1 Jul 2025 until then); Kenya utility $0.0040 (KSh 0.52), Kenya marketing $0.0225–0.0248; Nigeria utility ≈ $0.0101 (≈₦14 at ₦1,340/$), Nigeria marketing ≈ $0.062 (≈₦84); billed in USD; BSPs (Termii etc.) add their own fees; the WhatsApp Business *app* is unaffected — [Meta pricing page (snippet)](https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing); [Business Daily Africa](https://www.businessdailyafrica.com/bd/markets/market-news/meta-sets-whatsapp-messaging-charges-5573670); [Legit.ng](https://www.legit.ng/business-economy/technology/1727481-whatsapp-charge-nigerian-businesses-message-october-1-what-companies-know/); [msmeafricaonline](https://msmeafricaonline.com/whatsapp-to-charge-businesses-for-customer-replies-from-october-2026/) [primary snippet + secondary; Nigeria figures conflict across sources]
- Termii described as API-first, $50/month per WhatsApp Business Account plus pay-as-you-go — [AiSensy Nigeria providers](https://m.aisensy.com/blog/best-whatsapp-api-providers-nigeria/) [secondary]
- **Meshtastic/LoRa**: payload ~233 bytes (DATA_PAYLOAD_LEN, excl. 16-byte header) or 51–222 bytes depending on spreading factor; throughput 5–20 B/s in typical configs, ~50 B/s worst-case reliable, up to ~1,265 B/s raw on Short/Fast between two nodes; default Long Fast = 250 kHz BW, SF11, CR 4/5 — [Meshtastic forum text limit](https://meshtastic.discourse.group/t/whats-the-text-limit/11440); [Linux Magazine Meshtastic](https://www.linuxpromagazine.com/Issues/2025/299/Meshtastic); [Meshtastic multimedia thread](https://meshtastic.discourse.group/t/how-can-i-send-multimedia-files-through-meshtastic/2867) [secondary/community]
- Okada's `degraded_max_tokens: 300` is explicitly the byte-cutting lever on degraded links — [config](/home/user/okada-router/config) [verified local]

### Inferences
- **Token streaming relay**: llama-server and all four cloud providers already speak OpenAI SSE; the change is to pass `stream=true` upstream and re-chunk, with the resilience trick being *mid-stream failover* (if a cloud stream dies after N tokens, resume on the next rung with the partial text as assistant prefix). This is plumbing, no research needed. [estimate]
- **Queue replay**: write full request bodies (encrypted) to SQLite with a WAL, replay on startup, keep the current JSONL as audit log; add idempotency keys so a client retry after reconnect does not double-run. [estimate]
- **Semantic cache**: run `all-MiniLM-L6-v2`/`bge-small` via ONNX Runtime or `nomic-embed-text` GGUF via the existing llama-server (`--embedding`), store vectors in SQLite (sqlite-vec) or a flat numpy index — the box has at most a few thousand entries, so no vector DB. Namespace the key by tenant + system-prompt hash + language; the literature says the threshold must be tuned per workload, so ship it with a per-tenant knob and log near-miss pairs for tuning. Measured 5–9 ms per embedding on laptop CPUs means cache lookup is cheaper than any network probe. [estimate from cited latencies]
- **PII and encryption**: nothing Africa-specific; standard stack is a local PII detector (Presidio-style, CPU) applied before caching/logging, SQLCipher or OS-level disk encryption for queue/telemetry, per-tenant keys. Not verified in this session (search budget), noted as a gap. [estimate]
- **Store-and-forward over SMS/WhatsApp**: economics per answer ≈ ₦14 (WhatsApp utility, Nigeria) or ₦2–7 per 160-char SMS page (a 300-token answer is ~8 SMS pages ≈ ₦16–56) — so a WhatsApp utility message is now **cheaper per answer than SMS** for anything longer than two pages, while USSD remains session-priced and unsuited to free-text answers. The gateway should expose the queue result via a channel adapter (WhatsApp Cloud API webhook → `/okada/queue/{id}` result → reply template) and let SMS carry only short, templated replies. [estimate]
- **LoRa/mesh is not a channel for LLM answers**: at 5–50 B/s a 300-token (~1.2 kB) answer takes 25–240 s per hop and the 233-byte packet cap means fragmentation; it could carry *queue acknowledgements* or 1-line answers between an off-grid clinic and a box with backhaul, which is a demo, not a product. Reticulum/Briar were not researched (budget). [estimate]

## Key Question 6: Precedents — offline-first / low-bandwidth AI deployments in LMICs

### Takeaway
The successful African deployments (Jacaranda PROMPTS, Farmer.Chat, Rori, Ask Viamo Anything) all chose the *lowest-common-denominator channel* (SMS, WhatsApp, voice IVR) with the model in the cloud, invested in a fine-tuned mid-size model for the local language, and measured outcomes, not tokens/s. None of them run models on the end user's device; "offline" means the channel tolerates disconnection. Okada's distinctive contribution is the on-prem rung, which none of these has.

### Cited Findings
- **Jacaranda Health PROMPTS (Kenya/Ghana)**: SMS messages timed to pregnancy stage plus an AI-enabled helpdesk that triages questions and triggers referrals; UlizaMama/UlizaLlama is a Llama-3-based Swahili model; Ghana reach 95,000+ mothers with reported improvements in danger-sign recognition and clinic attendance (self-reported); Deep Learning Indaba 2025 poster on "designing and serving low-resource LLMs in maternal health settings" — [Jacaranda staff post (LinkedIn)](https://ke.linkedin.com/in/okeyo-gichana); [Sylvia Mbugua LinkedIn](https://ke.linkedin.com/in/sylvia-mbugua); [UlizaLlama HF card](https://huggingface.co/Jacaranda/UlizaLlama/blob/6775e74bddd064bae0aef38f93423f52bb0fd00a/README.md?code=true) [secondary + primary card]
- **Farmer.Chat (Digital Green)**: FY25 across India, Ethiopia, Kenya, Nigeria, Brazil; 165K questions; 70% of interactions in local languages; 60% of surveyed farmers took action; accessible via WhatsApp and Telegram; Kenya grew from 200 users to 14,000 users / 260,000 questions by end-2023; fine-tuned GPT-4o Mini to cut infra cost — [Digital Green FY25 report](https://digitalgreen.org/wp-content/uploads/2025/07/Digital-Green-FY25-Annual-Report.pdf); [GitLab Foundation](https://www.gitlabfoundation.org/our-journey/empowering-kenyan-farmers-how-ai-is-revolutionizing-agriculture-with-digital-green); [ICT4D abstract](https://ict4dconference.secure-platform.com/site/gallery/rounds/82002/details/10821); [TechXLab](https://techxlab.org/solutions/farmer-chat/) [self-reported]
- **Rori (Rising Academies, Ghana)**: WhatsApp math tutor; preliminary ~500-student study found growth-score effect size 0.36 (p<0.001), marginal cost ~$5/student, runs on basic phones over low bandwidth; follow-on government-school trial registered for 2025 (results not public); vendor claims 150,000+ students — [Stanford SCALE summary](https://scale.stanford.edu/publications/effective-and-scalable-math-support-experimental-evidence-impact-ai-math-tutor-ghana); [AEA registry 14476](https://www.socialscienceregistry.org/trials/14476); [Claude customer page](https://claude.com/customers/rising-academies) [primary study + promotional]
- **Ask Viamo Anything (Zambia pilot May 2023; Nigeria English, Tanzania Swahili, Pakistan Urdu, India Hindi in H1 2024)**: voice IVR over basic phones with no internet; 500 pilot users; 97.2% of SDG questions comprehended; >60% of interactions from women; health the top topic; rollout prioritised languages best supported by Whisper transcription — [GSMA write-up](https://www.gsma.com/solutions-and-impact/connectivity-for-good/mobile-for-development/gsma_resources/voice-first-generative-ai-for-impact-insights-from-viamos-ask-viamo-anything-pilot-in-zambia/); [Viamo AVA page](https://viamo.io/ask-viamo-anything-ai/); [BusinessWire](https://www.businesswire.com/news/home/20240315519318/en/Ask-Viamo-Anything-Combines-AI-with-Basic-Mobile-Calls-to-Bring-Next-Billion-Online) [self-reported + GSMA]
- WhatsApp's October 2026 switch to per-message utility billing directly raises the running cost of Rori/Farmer.Chat-style channels (see Q5 figures) — [Business Daily Africa](https://www.businessdailyafrica.com/bd/markets/market-news/meta-sets-whatsapp-messaging-charges-5573670) [secondary]

### Inferences
- Common lessons: (1) language support came from continued pretraining/fine-tuning of a 7B–8B model on a few hundred million local-language tokens (Jacaranda: 321M Swahili tokens), not from a 1B model; (2) channel choice beat model choice for adoption — SMS/WhatsApp/voice reach feature phones; (3) cost was managed by using smaller *hosted* models (GPT-4o Mini) rather than on-prem; (4) impact was measured with RCT-style designs, which is what funders and ministries ask for. [estimate]
- Okada's wedge relative to these: it is the *infrastructure* layer they lack (routing, offline queue, on-prem rung); the fastest route to relevance is to make Okada the backend for a PROMPTS/Rori-style WhatsApp bot and demonstrate "answered rate during outage" as the KPI. [estimate]

## Key Question 7: Comparable open-source architectures and distributed inference across a shop's phones

### Takeaway
LiteLLM is the closest architectural sibling for the key/budget/routing layer and the one to borrow from; llama.cpp's `llama-server` (already used) is the right local engine; exo-style distributed inference across phones is not realistic for a shop in 2026 because the partitioning is memory-weighted, the fast path is Thunderbolt-5 Macs, and decode is bandwidth-bound.

### Cited Findings
- **LiteLLM proxy**: virtual keys, per-key/team budgets and spend tracking, rate limiting, routing with fallbacks, Prometheus metrics; deployable via Railway/Elestio templates — [elest.io](https://blog.elest.io/litellm-stop-burning-money-on-llm-apis-virtual-keys-cost-tracking-and-guardrails/); [Railway template](https://railway.com/deploy/litellm-ai-gateway) [secondary]
- **exo**: pools Macs, Raspberry Pis, smartphones; default "ring memory-weighted partitioning" assigns layers proportional to device memory; headline low-latency path is RDMA over Thunderbolt 5 (Mac-only); reviewers note unclear OS support, no Windows, and network-dependent latency; decode is memory-bandwidth-bound — [CNX exo](https://www.cnx-software.com/2025/02/18/exo-software-a-distributed-llm-solution-running-on-a-cluster-of-computers-smartphones-or-sbcs/); [aicoolies review](https://aicoolies.com/reviews/exo-review); [korben](https://korben.info/en/exo-create-ai-cluster-unused-devices.html) [secondary]
- **WebLLM**: OpenAI-shaped `chat.completions.create()` in-browser; 163 prebuilt models; WASM + WebGPU kernels compiled by MLC — [WebLLM paper](https://arxiv.org/html/2412.15803v1); [pinggy 2026](https://pinggy.io/blog/run_llm_in_browser_webgpu/) [primary + secondary]
- Okada's local provider already targets llama-server's OpenAI-compatible endpoint and treats local calls as outside the network simulator — [providers/llamacpp_provider.py](/home/user/okada-router/providers/llamacpp_provider.py) [verified local]

### Inferences
- Borrow from LiteLLM: virtual-key schema, budget/duration semantics, spend endpoints, model-group fallbacks. Borrow from llama.cpp server: `--parallel`, `--embedding`, slot save/restore for KV reuse across repeated system prompts (cheap "semantic-ish" speedup). Jan/LocalAI/llamafile/Ollama are packaging alternatives, not architecture to copy; llamafile's single-binary approach is worth copying *as a distribution format* for the Okada box (one file, no Docker). [estimate; Jan/LocalAI/llamafile not researched this session]
- Distributed inference across a shop's phones: no. Phones on a 2.4 GHz Wi-Fi hotspot give single-digit MB/s with high jitter; pipeline-parallel decode would move activations per token across that link, and exo's own design assumes Thunderbolt/RDMA for the fast path. A single RK3588/Jetson box plus thin clients is both cheaper and faster. What *is* realistic is **work distribution** (each phone runs its own tiny model for its own user, with the box as shared cache/queue), not model sharding. [estimate]
- Petals and Nous Psyche (internet-scale swarm training/inference) are irrelevant to a bandwidth-starved shop; not researched further.

### Gaps
- No measured exo throughput over Wi-Fi or across phones; the "not realistic" verdict is reasoning from its design, not a benchmark.
- Jan, LocalAI, llamafile, Open WebUI, Petals, Psyche: not researched (search budget).

## Summary answers to the founder's three questions (synthesis, [estimate] unless cited above)

1. **Do we need API keys?** Yes for the cloud rungs, but a pilot can run on stacked free tiers (Groq ~1,000 RPD, Gemini Flash ~1,500 RPD disputed, OpenRouter free 50–1,000 RPD, Cloudflare 10k Neurons/day, SambaNova 20 RPD). Build pooled-key + per-tenant virtual keys with hard budgets (LiteLLM pattern) and accept BYO keys as an override. The offline/local rung needs no key at all.
2. **Do we need to train?** Not to ship. Priorities in order: (i) change the telemetry schema to capture language-ID, hashed prompt and a quality label; (ii) evaluate Qwen2.5-1.5B/Qwen3-1.7B/Gemma-3-4B/InkubaLM on AfriQA + IrokoBench slices for Swahili/Hausa/Yoruba/Igbo/Pidgin locally; (iii) if gaps are large, a QLoRA adapter on Inkuba-Instruct/AfriQA/AfriSenti for ~$5–40 of A100 time; (iv) later, distil consented cloud answers into the local model; (v) a learned router only once there are ~10^4 labelled routing outcomes.
3. **What more can we build?** Token-streaming relay with mid-stream failover; durable SQLite queue with replay and idempotency; CPU semantic cache (MiniLM/bge-small/nomic via ONNX or llama-server) namespaced per tenant; WhatsApp Cloud API / SMS channel adapters that deliver queued answers (budget ~₦14 per WhatsApp utility reply in Nigeria, ~KSh 0.52 in Kenya); an Android SDK on llama.cpp/llama.rn that prefers the LAN box, caps local generation for thermals, and distributes GGUF weights over LAN; a reference "Okada box" on RK3588 (~22 tok/s on 1.5B) or Jetson Orin Nano Super (43 tok/s on 3B) with ~10 W draw for solar sites; translate-test pipeline for weak languages. Hype to avoid: NPU HATs for small LLMs (CPU is as fast at 1.5B on RK3588), sharding models across phones, LoRa as an answer channel, and 1B-class models for Yoruba/Igbo.
