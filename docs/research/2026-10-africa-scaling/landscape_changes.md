## Q1. New/updated small open-weight models (0.5B–8B) for CPU-only 8 GB machines, Aug–Oct 2026

### Takeaway
No new sub-10B base model shipped from Qwen, Google, Meta, Microsoft or OpenAI in the window; the Qwen3.8 release (Aug 12–14) is 27B and 2.4T only, so Qwen3.5 0.8B/2B/4B/9B (Mar 2 2026) remains the current small Qwen line and is a straightforward upgrade path from Qwen2.5 1.5B/3B. The one genuinely new small model in-window is NVIDIA's Nemotron 3.5 Bolt E4B (Oct 23), a Gemma 4 E4B fine-tune that ships with a DFlash speculative-decoding draft and GGUFs.

## Q2. llama.cpp / llama-server, Ollama, MLC, ExecuTorch, LiteRT, Apple Foundation Models, Android on-device changes; speculative decoding, KV cache, quantisation for CPU

### Takeaway
llama.cpp shipped two tagged releases in the window (v0.6.0 Oct 5, v0.7.0 Oct 15) with breaking llama-server changes Okada must handle: the **default port moved from 8080 to 9931**, formatted chat output became an array of parts, and prompt-cache/slot semantics changed; on the upside, CPU k-quant tiled matmul, Q2_0 AVX2 kernels, MTP/DFlash/LiliCorr speculative decoding and `--spec-type` presets arrived. Ollama moved to v0.40.x with OpenAI-compat streaming fixes and an Apple-Foundation-Model runner in review; ExecuTorch 1.5 and LiteRT 2.3 advanced on-device LLM serving; MLC-LLM shows no 2026 releases.

## Q3. What LiteLLM, OpenRouter, Portkey, Cloudflare AI Gateway, Vercel AI Gateway, Kong, Helicone, Not Diamond, Martian, RouteLLM shipped; any network-aware/offline fallback; direct "offline-first gateway" competitor

### Takeaway
The gateway market consolidated hard (Stripe–OpenRouter Aug 19; Portkey into Palo Alto; Helicone into Mintlify; TensorZero and Pydantic AI Gateway archived) and the open-source leader LiteLLM suffered a supply-chain compromise of release 1.107.0 on Oct 24 2026. No major gateway added client-side network-measured routing or offline fallback; the only "local fallback" players are small OSS projects (Swobu, RelayPlane, Olla, OSW, Ollama Herd, OpenClaw config) that route among local backends or do priority failover, none measuring network conditions.

## Q6. New products/research on offline-first LLM apps, semantic caching for gateways, queue-and-sync patterns

### Takeaway
Aug–Oct 2026 research on gateway semantic caching focused on robustness (LaCache, Aug 2026, defends against cache-collision/poisoning) building on earlier 2026 work (Krites asynchronous verified caching; continuous semantic caching), while offline-first LLM queueing remains an engineering pattern (durable outbox with idempotent mutation IDs, ordered drain with retry/backoff) rather than a product category.

### Cited Findings
- LaCache: "Robust Semantic Caching for LLM Serving" (arXiv 2608.01718, Aug 2026) targets cache-collision attacks where injected queries corrupt later legitimate responses, with a redesign claiming provable defence — [arXiv](https://arxiv.org/abs/2608.01718)
- Krites: asynchronous verified semantic caching using an LLM judge off the critical path; up to 3.9x more requests served from curated answers vs tuned baselines (arXiv 2602.13165, Feb 2026) **[background]** — [arXiv](https://arxiv.org/html/2602.13165)
